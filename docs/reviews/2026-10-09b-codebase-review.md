| 1 | Correctness - dead feature, verified in the shipped release | High | native/src/p_tokens.c:627-647 (write), 572-625 (read) | `tokCursorSave` writes the cursor path straight into a JSON string with no escaping. Windows paths are `\\wsl.localhost\Ubuntu\home\...`, so every separator becomes an invalid JSON escape (`\U`, `\h`, `\.`), which jsmn rejects (`jsmn_parse_string`'s `default: return JSMN_ERROR_INVAL`, jsmn.h:243-252). **The load side then also does a raw `memcpy` with no unescaping** (p_tokens.c:594-597), so escaping the write alone would not round-trip. Consequence, proven from the live release binary's log at `C:\Users\tyanw\.wizbar\native.log`: launch 2 logs `tokCursorLoad: file=ok len=113077` and immediately `files=492 cursorHits=0 bytesRead=1054838010`, `scan took 46063 ms`; the very next in-process rescan logs `cursorHits=492 bytesRead=27675`, `scan took 1281 ms`. The file is written, read, and thrown away on **every launch**. Independently confirmed: `node -e "JSON.parse(...)"` on the live file fails with `Bad escaped character in JSON at position 21`. The in-process path works (`g_tokCursorN` is non-zero so the file is not re-read), which is why the bug survived: only a restart exposes it. The documented contract - "a per-file byte cursor means a warm rescan reads only appends" - is dead at every start, costing a ~1 GB / ~46 s cold read, and with `estimateMissingUsage` on by default the entire history is re-estimated each start. The failure is also silent: the debug line reads `file=ok`, which looks like success. | Inline |
| 2 | Correctness - stale cache after config reload | Medium | native/src/p_icons.c:326-339 (iconUserAdd), 700-715 (svgDraw) | `iconUserAdd` finds an existing name and rewrites `g_user[slot][0].path` / `.w` ("redefine = replace") but never invalidates the cached DIB. `svgDraw` re-renders only on `!d->valid \|\| d->color != color \|\| d->w != bw`, where `d->w` is the box size (`12 * g_scale`), not the stroke width - so a same-colour, same-DPI redefinition always hits the cache and blits the old bitmap. `iconDrop()` / `valid = 0` is reachable only from `iconDibMake` on a **size** change. `iconUserAdd` is called on every reload (p_ui.c:4011) and `configCheckTick` repaints after a save, so a user who edits `d` or `w` in `theme.icons[]`, saves, and lets the bar hot-reload keeps the old glyph until the colour or DPI changes or the bar restarts. The icon engine's whole purpose is config-defined icons, so this is the primary path. | Inline |
| 3 | Correctness - compounding over-count for flat-format stores | Low | native/src/p_tokens.c:707 | `if (cfg->tokEstimate && c && c->size > 0 && c->chars <= 0) from = 0;` forces a full re-read from byte 0 whenever a file's accumulated transcript total stayed 0. `tokTextLen` returns 0 for any line lacking the literal `"message":{` (it requires the nested pi shape), while `tokParseLine` is explicitly written to accept keys anywhere and its comment documents the flat shape `{"type":"assistant","usage":{...},"model":"...","timestamp":123}` - the `tokens.sources[].fields` indirection exists for exactly such harnesses. Re-staging is additive: records are filtered only by `r.ts > g_cacheMaxTs` (a timestamp filter, not a dedup), so re-reading from 0 re-stages every record above the seed boundary and `aggRecord` accumulates with `+=`. Blast radius is bounded by the unchanged-file skip at line 702 (which still works in-process), so only files that changed are re-read - but for a continuously appended flat-format file that means a full re-parse and a full re-add on every rescan, i.e. a silently compounding over-count. Not currently firing on this machine: both live stores (the pi store and `~/.zai/agent/sessions`) use the nested shape. | Inline |

## Notes for the fix round
- Finding 1 needs **both** sides changed: escape `\` and `"` on write, and decode `\\` / `\"` on read for both `path` and `real` (the load side's `memcpy` and `jstrCopyA` currently copy raw). A shared escape/unescape helper is the durable form; `jdup` (chocobar.c:305-345) is the existing model for wide strings.
- While there: make the failure visible instead of `file=ok` (log the parse result and length), and consider deleting a structurally unloadable cursor file so the next launch stops paying for it.
- Finding 2: clear the slot's cached DIB in `iconUserAdd` (or add a generation counter `svgDraw` compares, which also covers stroke-width changes at constant box size).
- Finding 3: distinguish "never counted" from "counted and genuinely zero" (a sentinel such as `-1`, or a per-cursor flag), so only the former forces a re-read.
